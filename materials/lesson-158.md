## 今回の学習

### 前回の復習

前回のレッスンでは、TODOアプリの完成版を作成しました。具体的には以下の内容を学習しました。

- **統合**: すべての機能を1つのアプリにまとめる方法
- **デバッグ**: バグを見つけて修正する技術
- **完成度**: アプリを完成させるための仕上げ作業

前回作成した「完成版TODOアプリ」により、フィルター、カテゴリ、検索、編集、バリデーション、統計、削除など、多くの機能を持つ実用的なアプリケーションを完成させました。

### 今回の目標

今回は、新しいプロジェクト「予算管理アプリ」の設計を行います。コードを書く前に、しっかりと設計を行うことで、より良いアプリケーションを作ることができます。

今回の学習で達成する目標は以下の通りです。

- **機能一覧作成**: どんな機能が必要かを洗い出す
- **画面設計**: ユーザーが見る画面をスケッチする
- **データ構造設計**: どんなデータを扱うかを決める

## プロジェクト設計とは

### なぜ設計が重要なのか

これまで、TODOアプリを作りながら、少しずつ機能を追加してきました。しかし、実際のプロジェクトでは、最初に「何を作るか」「どう作るか」を考えておくことが非常に重要です。

家を建てることを考えてみましょう。いきなり釘を打ち始めるのではなく、まず設計図を描きます。どこに部屋を配置するか、どのくらいの広さにするか、水道や電気の配線はどうするかを事前に決めておきます。これがないと、後で「ここにドアが欲しかった」「部屋が狭すぎた」といった問題が発生してしまいます。

プログラミングも同じです。設計をせずにコードを書き始めると、以下のような問題が起こります。

- **機能の漏れ**: 必要な機能を忘れてしまい、後から追加が大変になる
- **データ構造の不一致**: 後から「このデータ形式では不便だった」と気づいて、すべてを書き直すことになる
- **コードの混乱**: どこに何を書くか決まっていないと、コードがぐちゃぐちゃになる
- **手戻りの発生**: 何度も作り直すことになり、時間がかかる

設計をすることで、これらの問題を防ぎ、効率的に開発を進めることができます。

### 設計の3つのステップ

プロジェクト設計は大きく3つのステップに分かれます。

**1. 機能一覧作成（What：何を作るか）**

まず、アプリにどんな機能が必要かを考えます。「収入を記録したい」「支出を記録したい」「グラフで見たい」など、やりたいことをすべて書き出します。

これは料理のレシピを考えるときに、「材料は何が必要か」を書き出すようなものです。必要なものをすべて揃えてから調理を始めると、途中で「あの材料がない」と慌てることがありません。

**2. 画面設計（How：どう見せるか）**

次に、ユーザーが見る画面を考えます。どこにボタンを置くか、どこに情報を表示するか、どんな色やレイアウトにするかを決めます。

これは料理の盛り付けを考えるようなものです。どんなお皿に、どう並べると美味しそうに見えるかを考えます。見た目が良いと、使いやすさも向上します。

**3. データ構造設計（What：何を記憶するか）**

最後に、アプリが扱うデータの形を決めます。収入のデータには「金額」「日付」「カテゴリ」などが必要です。これをどんな形式で保存するかを設計します。

これは料理の下ごしらえのようなものです。野菜をどのサイズに切るか、肉はどう処理するかを決めておくと、調理がスムーズに進みます。

## 予算管理アプリの概要

### 作成するアプリの全体像

今回から作成する「予算管理アプリ」は、家計簿のようなアプリケーションです。収入と支出を記録して、お金の流れを管理できるようにします。

多くの人が、「今月いくら使ったかな」「何にお金を使いすぎているかな」と悩んだ経験があるでしょう。このアプリを使うと、収入と支出を記録して、グラフで可視化できるようになります。

### 参考にする既存のアプリ

世の中には似たようなアプリがたくさんあります。

- **Zaim、マネーフォワード**: 人気の家計簿アプリです。銀行と連携したり、レシートをスキャンできたりします
- **Excelの家計簿テンプレート**: 多くの人が使っている表計算での管理方法です
- **手書きの家計簿**: 昔ながらのノートに記録する方法です

これらのアプリの良いところを参考にしながら、シンプルで使いやすいアプリを作っていきます。

## ステップ1：機能一覧の作成

### 必要な機能を洗い出す

まず、予算管理アプリに必要な機能をすべて書き出します。ユーザーが「こんなことをしたい」と思うことを想像して、リストアップしていきます。

#### 基本機能

**収入の管理**
- 収入を登録できる（金額、日付、カテゴリ）
- カテゴリの例：給料、ボーナス、副業、お小遣い
- 登録した収入を一覧で見られる
- 収入を編集・削除できる

**支出の管理**
- 支出を登録できる（金額、日付、カテゴリ、メモ）
- カテゴリの例：食費、交通費、娯楽、光熱費、家賃
- 登録した支出を一覧で見られる
- 支出を編集・削除できる

#### データの可視化

**グラフ表示**
- カテゴリ別の支出を円グラフで表示する
- 月別の収支を棒グラフで表示する
- グラフを見ると、パッと全体像が分かる

**統計情報**
- 今月の収入合計を表示する
- 今月の支出合計を表示する
- 収支（収入 - 支出）を表示する
- カテゴリ別の集計を表示する

#### データの管理

**データの保存と読み込み**
- localStorageを使ってデータを保存する
- ブラウザを閉じても、次に開いたときにデータが残っている
- データを読み込んで、前回の続きから使える

**データのエクスポート・インポート**
- データをCSVファイルとしてダウンロードできる
- CSVファイルをExcelで開いて確認できる
- データをJSON形式でエクスポート・インポートできる
- バックアップとして保存できる

#### UI/UX機能

**使いやすさの向上**
- 日付の入力を簡単にする（カレンダー選択）
- カテゴリを色分けして、見やすくする
- スマートフォンでも使えるレスポンシブデザイン
- アニメーションで操作をわかりやすくする

### 機能の優先順位付け

すべての機能を一度に作るのは大変です。そこで、優先順位を付けて、重要な機能から作っていきます。

**優先度：高（必須機能）**
- 収入の登録・表示・削除
- 支出の登録・表示・削除
- 基本的な統計（合計金額、収支）
- localStorageでのデータ保存

**優先度：中（あると便利な機能）**
- カテゴリ別の集計
- 月別の表示
- データの編集機能
- 簡単なグラフ表示

**優先度：低（追加機能）**
- CSVエクスポート・インポート
- アニメーション
- レスポンシブデザイン
- 高度なグラフ（複数種類）

この優先順位に従って、まず「優先度：高」の機能を完成させ、次に「優先度：中」、最後に「優先度：低」を実装していきます。

## ステップ3：データ構造設計

### 扱うデータを定義する

アプリが扱うデータの形を決めます。これが決まっていないと、後で「このデータが足りない」「この形式では不便だった」ということになります。

#### 収入データの構造

1つの収入データには、以下の情報が必要です。

```javascript
{
  id: 1,                           // 一意なID（自動生成）
  type: 'income',                  // 種類（収入）
  amount: 250000,                  // 金額（円）
  date: '2025-11-20',             // 日付
  category: '給料',                // カテゴリ
  memo: '11月分の給料'             // メモ（任意）
}
```

**各フィールドの説明**

- **id**: データを区別するための番号です。編集や削除のときに、どのデータかを特定するために使います
- **type**: 収入か支出かを区別します。後でフィルタリングするときに便利です
- **amount**: 金額を数値で保存します。文字列ではなく数値にすることで、合計や平均を計算しやすくなります
- **date**: 日付を文字列で保存します。YYYY-MM-DD形式にすると、並び替えが簡単です
- **category**: カテゴリ名を保存します。後で「給料の収入だけを見る」といったフィルタリングができます
- **memo**: 自由なメモを保存します。任意なので、空でも構いません

#### 支出データの構造

支出データも収入データと同じ形式にします。

```javascript
{
  id: 2,                           // 一意なID（自動生成）
  type: 'expense',                 // 種類（支出）
  amount: 3000,                    // 金額（円）
  date: '2025-11-21',             // 日付
  category: '食費',                // カテゴリ
  memo: 'スーパーで買い物'         // メモ（任意）
}
```

収入と支出を同じ形式にすることで、コードの共通化ができます。`type`フィールドで区別すれば、1つの配列で両方を管理できます。

#### カテゴリの定義

収入と支出のカテゴリを事前に定義しておきます。

**収入のカテゴリ**
```javascript
const incomeCategories = [
  { name: '給料', color: '#4CAF50' },
  { name: 'ボーナス', color: '#8BC34A' },
  { name: '副業', color: '#CDDC39' },
  { name: 'お小遣い', color: '#FFC107' },
  { name: 'その他', color: '#9E9E9E' }
];
```

**支出のカテゴリ**
```javascript
const expenseCategories = [
  { name: '食費', color: '#F44336' },
  { name: '交通費', color: '#E91E63' },
  { name: '娯楽', color: '#9C27B0' },
  { name: '光熱費', color: '#673AB7' },
  { name: '家賃', color: '#3F51B5' },
  { name: '通信費', color: '#2196F3' },
  { name: '医療費', color: '#03A9F4' },
  { name: 'その他', color: '#9E9E9E' }
];
```

各カテゴリに色を割り当てることで、グラフや一覧表示で視覚的に区別しやすくなります。

#### 全データの構造

すべてのデータを1つの配列で管理します。

```javascript
const transactions = [
  {
    id: 1,
    type: 'income',
    amount: 250000,
    date: '2025-11-20',
    category: '給料',
    memo: '11月分の給料'
  },
  {
    id: 2,
    type: 'expense',
    amount: 3000,
    date: '2025-11-21',
    category: '食費',
    memo: 'スーパーで買い物'
  },
  {
    id: 3,
    type: 'expense',
    amount: 500,
    date: '2025-11-22',
    category: '交通費',
    memo: 'バス代'
  }
];
```

この配列をlocalStorageに保存すれば、データの永続化ができます。

### データの保存形式

localStorageにデータを保存するときは、JSON形式に変換します。

```javascript
// 保存
localStorage.setItem('transactions', JSON.stringify(transactions));

// 読み込み
const savedData = localStorage.getItem('transactions');
const transactions = savedData ? JSON.parse(savedData) : [];
```

これにより、ブラウザを閉じても、次に開いたときにデータが復元されます。

## 設計のポイント

### 良い設計の特徴

**1. シンプルである**
複雑すぎる設計は、実装が大変になります。最初はシンプルに始めて、必要に応じて拡張していくのが良い方法です。

「給料と副業の収入を別々のデータ構造で管理しよう」と考えるより、「収入は1つのデータ構造で、カテゴリで区別しよう」と考えた方がシンプルです。

**2. 拡張しやすい**
後から機能を追加しやすい設計にします。

例えば、最初は「収入と支出だけ」だったとしても、後で「貯金の管理も追加したい」となったときに、データ構造を大きく変えなくて済むように設計します。

**3. 一貫性がある**
似たような機能は、似たような設計にします。

収入の登録と支出の登録は、ほとんど同じ処理です。だから、同じデータ構造、同じ関数で処理できるようにします。これにより、コードの重複を減らせます。

**4. ユーザー目線である**
プログラマーにとって都合の良い設計ではなく、ユーザーにとって使いやすい設計を心がけます。

例えば、「日付を入力してください」と言われたとき、「20251123」のような数値より、「2025-11-23」のような形式の方が分かりやすいですし、カレンダーから選べると更に便利です。

### よくある設計の失敗

**1. 設計をしないで始める**
いきなりコードを書き始めると、途中で「あれ、このデータをどう扱えばいいんだろう」と迷います。少し時間をかけて設計すると、結果的に開発が速くなります。

**2. 完璧を求めすぎる**
設計に時間をかけすぎて、いつまでたってもコードを書き始めないのも問題です。80%くらいの完成度で設計を終えて、実装しながら修正していくのが現実的です。

**3. 設計を変更しない**
開発を進めると、「この設計は良くなかった」と気づくことがあります。そのときは、素直に設計を変更しましょう。最初の設計に固執すると、使いにくいアプリになります。

## 4. データ構造

### トランザクション（取引）データ

1件の取引データの形式：

```javascript
{
  id: 1,                           // 一意なID（数値、自動生成）
  type: 'income',                  // 種類: 'income'（収入）または 'expense'（支出）
  amount: 250000,                  // 金額（数値、円単位）
  date: '2025-11-20',             // 日付（文字列、YYYY-MM-DD形式）
  category: '給料',                // カテゴリ名（文字列）
  memo: '11月分の給料'             // メモ（文字列、任意）
}
```

## まとめ

お疲れ様でした。今回のレッスンでは、プロジェクト設計の基本を学びました。

**今回学んだキーポイント**

**プロジェクト管理**
コードを書く前に、何を作るか、どう作るかを考えることの重要性を学びました。設計をすることで、機能の漏れや手戻りを防ぎ、効率的に開発を進められます。家を建てるときに設計図が必要なように、プログラミングでも設計が必要です。

**設計手法**
設計は3つのステップに分かれます。1つ目は「機能一覧作成」で、何を作るかを決めます。2つ目は「画面設計」で、ユーザーが見る画面を考えます。3つ目は「データ構造設計」で、どんなデータを扱うかを決めます。この順番で考えると、整理しやすくなります。

**設計書の作成**
考えた内容を設計書としてまとめることで、後で見返すときや、他の人に説明するときに役立ちます。設計書は一度作ったら終わりではなく、開発を進めながら更新していきます。設計書は「計画を記録するノート」です。

**データ構造の重要性**
データの形を最初に決めておくと、後の実装がスムーズになります。収入と支出を同じ形式にすることで、コードを共通化できます。IDを付けることで、編集や削除が簡単になります。

**優先順位付け**
すべての機能を一度に作るのは大変です。優先度を付けて、重要な機能から作っていきます。「優先度：高」の機能が完成したら、次は「優先度：中」、最後に「優先度：低」と進めます。これにより、途中で時間切れになっても、最低限の機能は完成しています。
