## 日常生活の例

### 例1：家を建てる過程

家を建てることを想像してください。

**設計なしで始めた場合：**
```
大工さん「じゃあ、とりあえず柱を立てましょう」
あなた「ちょっと待って、部屋の数は？」
大工さん「あ、決めてませんでした...」
あなた「キッチンはどこ？お風呂は？」
大工さん「それも考えてませんでした...」
```

これでは家は建ちません。何度も作り直すことになり、時間もお金も無駄になります。

**設計してから始めた場合：**
```
1. 設計図を描く
   - 部屋は3つ
   - キッチンは南側
   - お風呂は北側
   - 電気・水道の配線も決める

2. 設計図を見ながら建てる
   - 迷わず作業できる
   - 完成形がイメージできる
   - 必要な材料が分かる
```

プログラミングも同じです。設計図（設計書）を作ってから実装すると、スムーズに進みます。

## プロジェクト設計とは

### 設計が重要な理由

**設計をしないと起こる問題：**

1. **機能の漏れ**
   ```
   実装中「あ、削除機能を忘れてた...」
   → 後から追加するのは大変
   → データ構造も変更が必要
   ```

2. **データ構造の不一致**
   ```
   実装中「この形式では不便だった...」
   → すべてのコードを書き直し
   → 何日もかかる
   ```

3. **コードの混乱**
   ```
   実装中「この機能、どこに書こう？」
   → あちこちに散らばる
   → 読みにくいコードになる
   ```

4. **手戻りの発生**
   ```
   実装中「やっぱり最初から作り直そう...」
   → 時間の無駄
   → やる気がなくなる
   ```

**設計をすると得られる効果：**

1. **迷わず実装できる**
   - 何を作るかが明確
   - どこに何を書くかが分かる

2. **効率的に開発できる**
   - 必要な機能が分かっている
   - 優先順位が明確

3. **バグが減る**
   - データ構造が整理されている
   - 処理の流れが明確

4. **チームで開発しやすい**
   - 設計書を見れば全体像が分かる
   - 役割分担がしやすい

### 設計の3つのステップ

プロジェクト設計は、大きく3つのステップに分かれます。

#### ステップ1：機能一覧作成（What - 何を作るか）

**目的：** アプリにどんな機能が必要かを洗い出す

```
質問：「このアプリで何ができるようにしたい？」

回答例：
- 収入を記録したい
- 支出を記録したい
- グラフで見たい
- カテゴリ別に集計したい
- データを保存したい
```

料理のレシピで、「材料は何が必要か」を書き出すようなものです。

#### ステップ2：画面設計（How - どう見せるか）

**目的：** ユーザーが見る画面を考える

```
質問：「どこに何を表示する？」

回答例：
- 上部にタブメニュー
- 左側に入力フォーム
- 右側に統計情報
- 下部に一覧表示
```

料理の盛り付けで、「どう並べると美味しそうか」を考えるようなものです。

#### ステップ3：データ構造設計（What - 何を記憶するか）

**目的：** アプリが扱うデータの形を決める

```
質問：「どんな情報を保存する？」

回答例：
- 金額（数値）
- 日付（文字列）
- カテゴリ（文字列）
- メモ（文字列）
```

料理の下ごしらえで、「野菜をどのサイズに切るか」を決めるようなものです。

## 予算管理アプリの概要

### 作成するアプリの全体像

今回から作成する「予算管理アプリ」は、家計簿のようなアプリケーションです。

**アプリの目的：**
- 収入と支出を記録する
- お金の流れを可視化する
- 何にお金を使っているか分かる

**想定するユーザー：**
- 家計簿をつけたい人
- お小遣いを管理したい学生
- 副業の収支を管理したいフリーランス

**解決する問題：**
```
ユーザーの悩み：
「今月いくら使ったかな？」
「何にお金を使いすぎているかな？」
「貯金できているかな？」

アプリで解決：
✓ 収支が一目で分かる
✓ カテゴリ別の支出が分かる
✓ グラフで可視化できる
```

### 参考にする既存のアプリ

世の中には似たようなアプリがたくさんあります。

**人気の家計簿アプリ：**
- **Zaim** - シンプルで使いやすい
- **マネーフォワード** - 銀行と連携できる
- **Excelの家計簿** - 自分でカスタマイズできる

**良いところを参考にする：**
- カテゴリ別に色分け → 見やすい
- グラフで可視化 → 全体像が分かる
- 入力が簡単 → 続けやすい

私たちのアプリは、これらの良いところを取り入れて、シンプルで使いやすいアプリを作ります。

## ステップ1：機能一覧の作成

### 必要な機能を洗い出す

まず、予算管理アプリに必要な機能をすべて書き出します。

#### 基本機能

**収入の管理：**
```
□ 収入を登録できる
  - 金額を入力
  - 日付を入力
  - カテゴリを選択（給料、ボーナス、副業など）

□ 登録した収入を一覧で見られる
  - 日付順に表示
  - カテゴリで色分け

□ 収入を編集・削除できる
  - 間違えた時に修正できる
  - 不要なデータを削除できる
```

**支出の管理：**
```
□ 支出を登録できる
  - 金額を入力
  - 日付を入力
  - カテゴリを選択（食費、交通費、娯楽など）
  - メモを入力（任意）

□ 登録した支出を一覧で見られる
  - 日付順に表示
  - カテゴリで色分け

□ 支出を編集・削除できる
  - 間違えた時に修正できる
  - 不要なデータを削除できる
```

#### データの可視化

**グラフ表示：**
```
□ カテゴリ別の支出を円グラフで表示
  - どのカテゴリにお金を使っているか一目で分かる
  - 色分けして見やすく

□ 月別の収支を棒グラフで表示
  - 収入と支出の推移が分かる
  - 貯金できているか分かる
```

**統計情報：**
```
□ 今月の収入合計を表示
  - 大きな文字で目立たせる

□ 今月の支出合計を表示
  - 赤色で表示

□ 収支（収入 - 支出）を表示
  - プラスなら緑色
  - マイナスなら赤色

□ カテゴリ別の集計を表示
  - カテゴリごとの金額と割合
```

#### データの管理

**データの保存と読み込み：**
```
□ localStorageでデータを保存
  - ブラウザを閉じてもデータが残る
  - 自動保存される

□ データを読み込む
  - ページを開いたら前回の続きから使える
```

**データのエクスポート・インポート：**
```
□ CSVファイルとしてダウンロード
  - Excelで開いて確認できる
  - バックアップとして保存できる

□ JSONファイルでエクスポート・インポート
  - データのバックアップ
  - 別のブラウザにデータを移動できる
```

#### UI/UX機能

**使いやすさの向上：**
```
□ 日付の入力を簡単にする
  - カレンダーで選択できる

□ カテゴリを色分けする
  - 見やすく、分かりやすく

□ スマートフォンでも使える
  - レスポンシブデザイン

□ アニメーションで操作をわかりやすく
  - 追加時にフェードイン
  - 削除時にフェードアウト
```

### 機能の優先順位付け

すべての機能を一度に作るのは大変です。優先順位を付けて、重要な機能から作っていきます。

**優先度：高（必須機能）**
```
まず最初に作る機能：
✓ 収入の登録・表示・削除
✓ 支出の登録・表示・削除
✓ 基本的な統計（合計金額、収支）
✓ localStorageでのデータ保存

理由：これがないとアプリとして成立しない
```

**優先度：中（あると便利な機能）**
```
基本機能ができてから作る：
○ カテゴリ別の集計
○ 月別の表示
○ データの編集機能
○ 簡単なグラフ表示

理由：あると便利だが、なくても使える
```

**優先度：低（追加機能）**
```
最後に作る機能：
△ CSVエクスポート・インポート
△ アニメーション
△ レスポンシブデザイン
△ 高度なグラフ（複数種類）

理由：あれば嬉しいが、時間がなければ省略できる
```

**開発の進め方：**
```
1. 優先度：高 を完成させる
   → 基本的なアプリとして動く

2. 優先度：中 を追加する
   → 便利で使いやすくなる

3. 優先度：低 を追加する
   → さらに機能が充実する
```

この順番で進めると、途中で時間切れになっても、最低限使えるアプリは完成しています。

## ステップ3：データ構造設計

### 扱うデータを定義する

アプリが扱うデータの形を決めます。

#### 収入データの構造

1つの収入データには、以下の情報が必要です。

```javascript
// 収入データの例
{
  id: 1,                           // 一意なID（自動生成）
  type: 'income',                  // 種類（収入）
  amount: 250000,                  // 金額（円）
  date: '2025-11-20',             // 日付
  category: '給料',                // カテゴリ
  memo: '11月分の給料'             // メモ（任意）
}
```

**各フィールドの説明：**

```
id（アイディー）:
- データを区別するための番号
- 編集や削除のときに、どのデータかを特定する
- 自動で連番を生成する（1, 2, 3...）

type（タイプ）:
- 収入か支出かを区別する
- 'income'（収入）または 'expense'（支出）
- フィルタリングするときに便利

amount（アマウント）:
- 金額を数値で保存
- 文字列ではなく数値にすることで計算しやすい
- 例：250000（25万円）

date（デート）:
- 日付を文字列で保存
- YYYY-MM-DD形式（2025-11-20）
- この形式だと並び替えが簡単

category（カテゴリー）:
- カテゴリ名を保存
- 例：'給料', 'ボーナス', '副業'
- 後で「給料の収入だけ見る」といったフィルタリングができる

memo（メモ）:
- 自由なメモを保存
- 任意なので、空でも構わない
- 例：'11月分の給料', 'ボーナス（夏）'
```

#### 支出データの構造

支出データも収入データと同じ形式にします。

```javascript
// 支出データの例
{
  id: 2,                           // 一意なID（自動生成）
  type: 'expense',                 // 種類（支出）
  amount: 3000,                    // 金額（円）
  date: '2025-11-21',             // 日付
  category: '食費',                // カテゴリ
  memo: 'スーパーで買い物'         // メモ（任意）
}
```

**収入と支出を同じ形式にする理由：**

```
メリット1：コードの共通化
- 同じ関数で処理できる
- コードの重複を減らせる

メリット2：管理が簡単
- 1つの配列で両方を管理できる
- typeフィールドで区別できる

メリット3：拡張しやすい
- 後で新しい種類を追加しやすい
- 例：'saving'（貯金）を追加できる
```

#### カテゴリの定義

収入と支出のカテゴリを事前に定義しておきます。

**収入のカテゴリ：**

```javascript
const incomeCategories = [
  { name: '給料', color: '#4CAF50' },
  { name: 'ボーナス', color: '#8BC34A' },
  { name: '副業', color: '#CDDC39' },
  { name: 'お小遣い', color: '#FFC107' },
  { name: 'その他', color: '#9E9E9E' }
];
```

**支出のカテゴリ：**

```javascript
const expenseCategories = [
  { name: '食費', color: '#F44336' },

  { name: '娯楽', color: '#9C27B0' },
```

### データの保存形式

localStorageにデータを保存するときは、JSON形式に変換します。

**保存の処理：**

```javascript
// 保存
function saveData() {
  // 配列をJSON文字列に変換
  const json = JSON.stringify(transactions);

  // localStorageに保存
  localStorage.setItem('transactions', json);
}
```

**読み込みの処理：**

```javascript
// 読み込み
function loadData() {
  // localStorageから取得
  const json = localStorage.getItem('transactions');

  // データがある場合
  if (json) {
    // JSON文字列を配列に変換
    transactions = JSON.parse(json);
  } else {
    // データがない場合は空配列
    transactions = [];
  }
}
```

**実行の流れ：**

```
保存の流れ：
transactions（配列）
  ↓ JSON.stringify()
'[{"id":1,...},{"id":2,...}]'（文字列）
  ↓ localStorage.setItem()
localStorageに保存

読み込みの流れ：
localStorageから取得
  ↓ localStorage.getItem()
'[{"id":1,...},{"id":2,...}]'（文字列）
  ↓ JSON.parse()
transactions（配列）
```

これにより、ブラウザを閉じても、次に開いたときにデータが復元されます。

似たような機能は、似たような設計にします。

## まとめ

お疲れ様でした。今回のレッスンでは、プロジェクト設計の基本を学びました。

### 今回学んだキーポイント

**1. プロジェクト管理の重要性**

コードを書く前に、何を作るか、どう作るかを考えることの重要性を学びました。設計をすることで、以下の効果が得られます：

- **機能の漏れを防ぐ** - 必要な機能をすべて洗い出すことで、後から「あの機能を忘れてた」ということがなくなります
- **手戻りを減らす** - データ構造を最初に決めておくことで、「この形式では不便だった」という問題を防げます
- **効率的に開発できる** - 何を作るかが明確なので、迷わず実装できます

家を建てるときに設計図が必要なように、プログラミングでも設計が必要です。

**2. 設計手法の3ステップ**

設計は3つのステップに分かれます：

1. **機能一覧作成（What - 何を作るか）** - アプリにどんな機能が必要かをリストアップします。料理のレシピで材料を書き出すようなものです
2. **画面設計（How - どう見せるか）** - ユーザーが見る画面を考えます。どこに何を配置するか、どんな色にするかを決めます
3. **データ構造設計（What - 何を記憶するか）** - アプリが扱うデータの形を決めます。どんな情報を保存するか、どんな形式で保存するかを設計します

この順番で考えると、整理しやすくなります。

**3. 設計書の作成と活用**

考えた内容を設計書としてまとめることで、以下のメリットがあります：

- **後で見返すときに役立つ** - 「次に何を作るんだっけ？」と迷ったときに確認できます
- **他の人に説明しやすい** - チームで開発するときに、全体像を共有できます
- **進捗を管理できる** - チェックボックスで完成した機能を確認できます

設計書は一度作ったら終わりではなく、開発を進めながら更新していきます。設計書は「計画を記録するノート」です。

**4. データ構造の重要性**

データの形を最初に決めておくと、後の実装がスムーズになります：

- **収入と支出を同じ形式にする** - コードを共通化できます。`type`フィールドで区別すれば、1つの配列で管理できます
- **IDを付ける** - 編集や削除が簡単になります。どのデータかを特定できます
- **数値は数値で保存** - 文字列ではなく数値で保存することで、計算がしやすくなります

データ構造が整理されていると、バグも減ります。

**5. 優先順位付けの重要性**

すべての機能を一度に作るのは大変です。優先度を付けて、重要な機能から作っていきます：

- **優先度：高（必須機能）** - これがないとアプリとして成立しない機能です。まずこれを完成させます
- **優先度：中（あると便利な機能）** - あると便利ですが、なくても使える機能です
- **優先度：低（追加機能）** - あれば嬉しいですが、時間がなければ省略できる機能です

この順番で進めると、途中で時間切れになっても、最低限の機能は完成しています。
