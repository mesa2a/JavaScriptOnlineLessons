# Lesson 003ex: なぜ小数の計算で誤差が生じるのか

---

## はじめに

この教材は、レッスン3の補足資料です。本編で「小数の計算には若干の誤差が生じることがある」と説明しましたが、なぜそのような誤差が生じるのかを詳しく解説します。

この内容は初心者の段階では理解できなくても全く問題ありません。「そういうものなんだ」と知っておくだけで十分です。興味がある方、将来的に深く理解したい方のための参考資料としてお読みください。

---

## 小数の誤差を体験してみよう

まず、実際に誤差を確認してみましょう。コンソールで以下のコードを実行してください。

```javascript
console.log(0.1 + 0.2)
```

**実行結果**
```
0.30000000000000004
```

0.1 + 0.2 は 0.3 になるはずですが、結果は `0.30000000000000004` という不思議な数字になります。これがコンピュータの小数計算における誤差です。

もう一つ試してみましょう。

```javascript
console.log(0.1 + 0.1 + 0.1)
```

**実行結果**
```
0.30000000000000004
```

0.1 を3回足しても、0.3 ぴったりにはなりません。

---

## なぜ誤差が生じるのか

### コンピュータは2進数で計算する

コンピュータの内部では、すべての数字を「2進数」で表現しています。

私たちが普段使っている数字は「10進数」です。0から9までの10種類の数字を使い、10になると桁が上がります。一方、2進数は0と1の2種類の数字だけを使い、2になると桁が上がります。

| 10進数 | 2進数 |
|--------|-------|
| 0 | 0 |
| 1 | 1 |
| 2 | 10 |
| 3 | 11 |
| 4 | 100 |
| 5 | 101 |

コンピュータが2進数を使う理由は、電気のON/OFFで数字を表現できるからです。ONを1、OFFを0として、すべての計算を行っています。

### 10進数で表せるが2進数で表せない数

ここで問題が生じます。10進数では簡単に表せる数字でも、2進数では無限に続く小数になってしまうことがあるのです。

身近な例で考えてみましょう。10進数で「1/3」を小数で表すと、

```
1 ÷ 3 = 0.33333...
```

3が無限に続きます。どこかで打ち切らないと表現できません。

同じように、10進数の「0.1」を2進数で表すと、

```
0.1（10進数）= 0.0001100110011...（2進数）
```

0011のパターンが無限に繰り返されます。

### 有限のビット数で表現する限界

コンピュータは無限の桁数を扱えません。JavaScriptでは64ビット（64桁の2進数）で小数を表現しています。これはIEEE 754という国際規格で定められた形式です。

無限に続く2進数を64ビットで打ち切るため、わずかな誤差が生じます。これが「0.1 + 0.2 が 0.3 にならない」原因です。

---

## 具体的な仕組み（さらに詳しく）

### 浮動小数点数

コンピュータで小数を扱う方式を「浮動小数点数」といいます。これは、数字を「仮数部」と「指数部」に分けて表現する方法です。

例えば、123.45 という数字は、

```
1.2345 × 10²
```

と表現できます。1.2345が仮数部、2が指数部です。

コンピュータでも同様に、2進数の仮数部と指数部を使って小数を表現しています。

### なぜ「浮動」というのか

小数点の位置が「浮いて動く」ことから、浮動小数点数と呼ばれます。

```
123.45 = 1.2345 × 10²
0.12345 = 1.2345 × 10⁻¹
```

同じ仮数部1.2345でも、指数部を変えることで様々な大きさの数を表現できます。小数点の位置が指数部によって変わる（浮動する）のです。

---

## 誤差とどう付き合うか

### 誤差は避けられない

浮動小数点数を使う限り、この誤差は避けられません。これはJavaScriptだけでなく、Python、Java、C言語など、ほとんどのプログラミング言語で同じです。

### 実務での対処法

実際のプログラミングでは、以下のような方法で対処します。

**1. 整数で計算する**

金額の計算など、正確さが求められる場合は、小数を使わずに整数で計算します。

例えば、100.50円を扱う場合、10050（銭単位）として計算し、表示するときに100で割って50.50円にします。

```javascript
// 悪い例
console.log(100.50 + 200.75)  // 誤差が生じる可能性

// 良い例（銭単位で計算）
console.log((10050 + 20075) / 100)  // 301.25
```

**2. 誤差を許容する**

科学計算やグラフィックスなど、多少の誤差が許容される分野では、誤差を受け入れて使います。

**3. 専用のライブラリを使う**

金融システムなど、高い精度が求められる場合は、専用の数値計算ライブラリを使います。これは今後、必要になったときに学べば大丈夫です。

## 確認してみよう

誤差に関するいくつかの例を試してみましょう。

### 誤差が生じる例

```javascript
console.log(0.1 + 0.2)          // 0.30000000000000004
console.log(0.1 * 0.2)          // 0.020000000000000004
console.log(0.3 - 0.1)          // 0.19999999999999998
```

### 誤差が生じない例

```javascript
console.log(0.5 + 0.5)          // 1
console.log(0.25 + 0.25)        // 0.5
console.log(0.125 + 0.125)      // 0.25
```

0.5、0.25、0.125 などは2進数でちょうど表現できる数なので、誤差が生じません。これらは 1/2、1/4、1/8 という2のべき乗の分数だからです。

---

## まとめ

### 今回学んだこと

**なぜ誤差が生じるか**

1. コンピュータは内部で2進数を使っている
2. 10進数の0.1などは、2進数では無限小数になる
3. 有限のビット数で表現するために、どこかで打ち切る必要がある
4. その打ち切りによって、わずかな誤差が生じる

**覚えておくべきこと**

- 小数の計算では誤差が生じることがある
- これはJavaScriptの問題ではなく、コンピュータの仕組みによるもの
- 正確な計算が必要な場合は、整数で計算するなどの工夫が必要
